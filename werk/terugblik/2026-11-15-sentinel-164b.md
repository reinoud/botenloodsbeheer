# Terugblik Sentinel, nareview #164

**Datum:** 2026-11-15
**Taak:** nareview van de restpunten van de rekindeling-CSV (gh#164), na het herstel door de regie.

## Wat ging goed

De opdracht noemde precies welke punten openstonden, waar de vorige uitvoer stond en welk besluit voorging. Daardoor kon ik direct gericht toetsen. De code bevestigt de nieuwe tekst: de import roept `_rek_aanmaken` aan zonder `bootsoort_per_verdieping`, dus er komt geen `VerdiepingBootsoort`, en `indeling_instellen` geeft een nieuw vak dan een lege soortenlijst. De standaard is alleen te kiezen via Nieuw rek (`app/web/beheer.py:242`).

## Wat kon beter

De uitvoermap van de regie had twee m1-mappen. In de oudere stond de uitvoer van een eerdere versie van de test, maar de mutantkopie zelf stond er niet meer bij. Ik kon die runs dus niet naast de gestagede test leggen en heb m1 opnieuw opgebouwd.

## Wat deed je zelf goed

De mutant gemaakt uit `git show :<pad>` met een assert op precies één vervanging, en de diff tegen de index gecontroleerd vóór de run. De racetests draaiden met `-W error::pytest.PytestUnhandledThreadExceptionWarning`, zodat een fout in de tweede sessie niet als waarschuwing verdwijnt.

## Wat heb je onderweg verbeterd

Ik heb nagegaan waarom de nieuwe test m1 vangt, ook al vergrendelt de import de plaatsen nog wel: de plaatsquery ziet na het wachten de nieuwe plaats niet, omdat de snapshot van de query van vóór de commit is. Daardoor voegt de import het vak zelf toe en volgt een UniqueViolation.

## Wat kan structureel beter in de opdracht

Zet in de opdracht: "Bewaar naast de uitvoer van elke mutantrun de mutantkopie en het commando, in dezelfde map met tijdstempel, zodat een nareviewer de run kan herhalen."
