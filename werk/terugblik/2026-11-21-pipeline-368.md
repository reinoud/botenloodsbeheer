# Terugblik Pipeline, #368

Datum: 2026-11-21. Taak: de 404 van Traefik in de release-E2E verklaren en afvangen, en `draai.sh` het token van de dev-stack laten staan in een eigen project.

## Wat ging goed
Het log van run 1 van #356 stond nog in de scratchpad van Pipeline-356. Daaruit bleek de tijdlijn: de 404 viel in het venster van de test zelf, niet vlak na de `up`. Een proef met een PUT met alleen een te grote `Content-Length` geeft 413 van de router van de API zelf en bereikt de API niet. Zo kan `draai.sh` op de router wachten zonder token en zonder regel in het log van de API.

## Wat kon beter
Het log van Traefik en de gezondheid van `api` in pl356 zijn weg na `down -v`, en de gebeurtenissen van Docker houden er maar 256 vast. De oorzaak is daardoor niet te bewijzen. Ik heb één keer `git stash` gebruikt om `docker compose config` vóór en na te vergelijken; de overlay vraagt daarvoor een worktree. Het was alleen `config`, maar het was niet volgens de afspraak.

## Wat deed ik zelf goed
Ik heb de herhaallogica van de integratiecontainer niet aangepast, al ligt daar de echte oplossing. Dat verandert hoe lang een beheerder wacht en hoort eerst bij apex en de stakeholder. Elke foutroute in `draai.sh` heb ik met een docker-stub geproefd op de versie uit de index, met de toestand van beide tokenbestanden erbij.

## Wat heb ik onderweg zelf verbeterd
De eerste stub gaf drie regels met losse `echo`'s; `grep -q` met `pipefail` brak daar op. Eén `printf` loste dat op. De melding bij een time-out noemt nu ook dat de integratiecontainer misschien niet draait, want de proef loopt via die container.

## Wat kan structureel beter in de opdracht
- Zet in de opdracht: "Een release-E2E bewaart vóór `down -v` het log van traefik, api en integratie en `docker inspect` van api in de scratchpad; zonder die logs is een eenmalige fout niet te verklaren."
- Zet in de opdracht: "De release-E2E start met `API_TOKEN_BESTAND=./secrets/api_token.<project>`, een vooraf aangemaakt bestand met mode 600, en verwijdert dat bestand na `down -v`."
