# Terugblik Sentinel, #368

Datum: 2026-11-21. Taak: review vóór commit van de gestagede diff voor #368 (wachtstap op de router, controle op het tokenbestand, melding van een importfout, `API_TOKEN_BESTAND`).

## Wat ging goed
De brief noemde per toetspunt wat statisch mocht en wat een run vroeg, en waar het log van de E2E-run stond. Daardoor hoefde ik geen dienst aan te raken. De terugblik van Pipeline gaf de tijdlijn van de 404, en die bleek nodig om criterium 1 te toetsen.

## Wat kon beter
Het log van de E2E-run is van project `botenloods`, niet van een eigen project. Criterium 2 (de dev-integratie houdt zijn token na een release-E2E in een eigen project) is daarmee alleen met een stub geproefd, niet in een echte run.

## Wat deed ik zelf goed
Ik heb de controle op het tokenbestand met een stub in mijn scratchpad op zes gevallen geproefd (eigen project, dev-stack, pad via `..`, eigen bestand, lege mount). Ook heb ik de twee controles op `docker compose config` en het opzoeken van de projectnaam los op de host nagelopen, alleen lezend.

## Wat heb ik onderweg verbeterd
Eerst wilde ik de wachtstap alleen op logica toetsen. De terugblik van Pipeline zegt dat de 404 in het venster van de test viel, niet vlak na de start. Daarom heb ik de wachtstap ook tegen criterium 1 gelegd: hij vangt het waargenomen geval niet af.
