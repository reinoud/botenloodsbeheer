# Terugblik Aegis, tweede securityreview #372

Datum: 2026-11-23
Taak: tweede securityreview van het herstel van de teller `traefik_404` (integratiecontainer), vóór de commit.

## Wat ging goed

De opdracht noemde de afgekeurde route, het herstel, de test en de vorige proef. Daardoor kon ik de proef direct uitbreiden tot vijf scenario's (PUT, `melden`, `terugschrijven`, flapperende router met een fout van de bron, flapperende router met de 409 van de veiligheidsgrens) en die naast de oude code draaien.

## Wat kon beter

Het herstel dicht de gemelde route, maar opent een nieuwe: een fout die de teller op 0 zet en de GET niet stillegt (bron, 409), afgewisseld met een 404 van Traefik op de GET, laat de bron elke twee minuten ophalen. De eerste review keek alleen naar de route PUT; de tweede review vond de wisselroute pas met een vergelijking tegen de oude code.

## Wat deed ik zelf goed

Ik heb elk scenario op de oude en de nieuwe code gedraaid. Het verschil (1 tegen 90 keer de bron in drie uur) maakt de bevinding toetsbaar. Ik heb een herstel van één regel uitgeprobeerd en de 65 unittests van de integratie daartegen gedraaid, met de map gemount in de testcontainer en zonder de werkmap te wijzigen.

## Wat heb ik onderweg zelf verbeterd

`sed -i ''` faalde in deze shell (GNU-sed in het pad); ik ben overgestapt op python3 voor tekstwijzigingen. Mijn eerste testpoging liep op het systeem-Python zonder pytest; daarna heb ik de dienst `test` uit de overlay gebruikt.
