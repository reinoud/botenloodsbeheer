# Terugblik aegis, securityreview issue #133

Datum: 2026-11-06. Taak: securityreview van de gestagede diff voor #133 (400 van de API als JSON).

## Wat ging goed

De brief noemde de bron van de 400, de toetsvragen en het verwachte gedrag per bron. Daardoor kon ik gericht proeven: direct op Gunicorn en via Traefik vanaf het netwerk `koppeling`.

## Wat kon beter

De brief noemde de lokale proxy op 127.0.0.1:8080 met Host `localhost`. Daar is geen router voor `/api/`; de API zit alleen op het entrypoint `intern` (poort 8081) vanaf `koppeling`. Die proef gaf eerst een 404 van Traefik.

## Wat deed je zelf goed

Ik heb de positieve controle via Traefik gedaan en gezien dat Traefik `%2F` zelf weigert met een lege 400 en `%61` normaliseert naar `a` vóór de routering. Zo is vastgesteld dat de JSON-400 de rate limit niet raakt en dat de documentatie over `%2F` niet klopt voor een client van buiten.

## Wat heb je onderweg verbeterd

Na de 404 via 8080 heb ik de routerregels in `docker-compose.yml` gelezen en de proef herhaald via `koppeling` op poort 8081, met controle van de toegangslog.

## Wat kan structureel beter

Zet in de opdracht: een reviewer van de API proeft via Traefik met `docker run --rm -i --network botenloods_koppeling --entrypoint python botenloods-app` naar `10.203.0.2:8081`, niet via 127.0.0.1:8080; Traefik weigert `%2F`, `%5C`, `%25` en `%00` in het pad zelf (compose.dev.yml), dus noem welke weigering van de applicatie komt en welke van Traefik.
