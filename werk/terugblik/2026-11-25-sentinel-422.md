# Terugblik sentinel, review #422

Datum: 2026-11-25. Taak: review vóór commit van #422 (vier dode regels van het oude menu uit `app/web/static/stijl.css`).

## Wat ging goed

De selectie van `draai.sh -k 'test_kijkers or test_import'` stond vooraf vast met `--collect-only` (7 tests). De run gaf 7 geslaagd, 0 gefaald en 0 overgeslagen in één samenvatting. De werkmap bleef ongemoeid: de CSS-varianten kwamen via `page.route` uit de scratchpad.

## Wat kon beter

De eerste schermafbeeldingen van `/profiel` waren byte-gelijk, maar de mutant ook. Op die pagina staat geen kop van het menu open, dus geen enkele `.dj-nav__link` was in beeld. Zonder de mutant uit de opdracht had ik een gelijke afbeelding als bewijs gemeld die niets bewees. Daarnaast verbruikt elke run van mijn script een uitnodiging; door een fout in mijn route-handler en de herhaling werden het drie beheerders (ids 23559, 23560, 23561, allemaal verwijderd).

## Wat deed ik zelf goed

Ik maakte de schermafbeeldingen pas na de E2E-run, zodat mijn inlogpogingen niet meetelden voor de rate limit van de run. Ik las de mutantafbeelding na en zag zo dat het menu dicht was. Ik controleerde per variant ook de berekende kleur van een menulink, zodat vaststond dat de vervangen CSS echt geladen was.

## Wat heb ik onderweg verbeterd

Het script opent nu in beide breedtes de kop Loods en wacht tot de link Rekoverzicht zichtbaar is voordat het de afbeelding maakt. Daarna gaf de mutant op 1100 en op 360 px een andere afbeelding, en waren `main` en gestaged byte-gelijk. Een `rm` op mijn oude afbeeldingen werd door de hook tegengehouden; ik schreef de nieuwe afbeeldingen in een verse map.

## Wat kan structureel beter

Zet in de opdracht: "Een schermafbeelding van het menu opent eerst een kop (bijvoorbeeld Loods) en wacht tot een menulink zichtbaar is; op een pagina zonder open kop staat geen menulink in beeld."

Zet in de opdracht: "Een Playwright-script dat inlogt via een uitnodiging, bewaart na het inloggen de `storage_state`, zodat een tweede run geen nieuwe beheerder vraagt."
