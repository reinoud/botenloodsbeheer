# Terugblik sentinel, review issue #105

**Datum:** 2026-11-05
**Taak:** review van de gestagede diff voor issue #105 (uv-image als eigen stage, Trivy-image in `docker/Dockerfile.trivy`)

## Wat ging goed

De brief noemde de vier toetspunten, de al gebouwde images en de bekende Trivy-melding (#124). Daardoor hoefde ik niets opnieuw uit te zoeken. Een herbouw van beide targets gaf dezelfde image-ID's als `proef105:app` en `proef105:dev`, dus de proefimages horen echt bij deze diff.

## Wat kon beter

De brief zei niet hoe de unitsuite op `proef105:dev` moet draaien. De dienst `test` gebruikt het image `botenloods-dev`. Ik heb een override-bestand in de scratchpad gemaakt (`image: proef105:dev`, `pull_policy: never`). Mijn eerste poging met `run --no-build` faalde, want die vlag bestaat niet bij `docker compose run`.

## Wat deed ik zelf goed

De bestandsnaamregel van Dependabot heb ik uit de bron van dependabot-core gehaald (`docker/lib/dependabot/docker/file_fetcher.rb`, `DOCKER_REGEXP = /dockerfile|containerfile/i`) en niet uit het geheugen. De folded `run: >` heb ik met PyYAML laten uitvouwen, zodat de quoting zichtbaar was zoals Actions hem krijgt.

## Wat heb ik onderweg zelf verbeterd

Ik zag dat de dienst `test` zonder override het gedeelde image `botenloods-dev` zou gebruiken. Dat image heb ik niet hertagd, want anderen gebruiken het. De override bleef in mijn scratchpad.

## Wat kan structureel beter in de opdracht of de afspraken

Zet in de opdracht: draai de unitsuite op een proefimage met `docker compose -f docker-compose.yml -f compose.dev.yml -f <scratchpad>/compose.<proef>.yml --profile test run --rm test pytest -q`, waarbij het override-bestand alleen `services.test.image: <proefimage>` en `pull_policy: never` zet; hertag `botenloods-dev` niet.
