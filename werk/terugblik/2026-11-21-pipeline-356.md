# Terugblik Pipeline, releasecontroles v2.2.0 (#356)

Datum: 2026-11-21. Taak: unitsuite, trivy, twee E2E-runs en de schermafbeeldingen op 31a6f9b.

## Wat ging goed
De opdracht nam de lessen van #347 over: eigen project, `KOPPELNET`, override zonder poorten en native images onder een eigen tag. Daardoor hoefde ik niets af te leiden. Unitsuite (1786) en trivy (app en integratie zonder bevindingen) waren groen bij de eerste poging; ze draaiden naast elkaar in ongeveer acht minuten.

## Wat kon beter
De hook Blast Radius hield de E2E-voorbereiding vast omdat de opdrachtregel de dienst `migrate` noemde, en kreeg binnen tien minuten geen antwoord. De E2E wachtte daardoor ruim zeven uur op het akkoord van de stakeholder.

Run 1 had één mislukte test: `test_beheerder_vraagt_import_aan_en_ziet_de_uitkomst`. Traefik van pl356 gaf om 12:21:39Z een 404 op `GET /api/v1/leden/importverzoek`; de API zag die aanvraag niet. De integratiecontainer wacht daarna een uur, dus de test bleef op "aangevraagd" staan. Run 2 was 58 van 58. Een losse herhaling met `-k` viel buiten het akkoord voor twee runs.

Na de runs geeft de integratiecontainer van de dev-stack HTTP 401: `draai.sh` zette een token van pl356 in `secrets/api_token`, en een herstart lost dat niet op.

## Wat deed ik zelf goed
Ik heb de hook niet omzeild, bijvoorbeeld door hetzelfde commando in een script te verstoppen. Ik heb de regie direct gemeld wat er vastzat en ben verdergegaan met het werk dat geen akkoord vroeg: native images `e2e356` (arm64 gecontroleerd), het runscript en de controle van de schermafbeeldingen.

## Wat heb ik onderweg zelf verbeterd
De images voor de E2E bouw ik nu met `docker build` buiten compose; dat raakt de dienst `migrate` niet en geeft dezelfde images. De telling draait met awk op de host, omdat Python alleen in de containers staat.

## Wat kan structureel beter
- Zet in de opdracht: "De release-E2E start de dienst `migrate` in een eigen project; vraag de stakeholder vóór de opdracht akkoord voor de hook Blast Radius (twee keer `up`, `draai.sh` en `down -v` in project pl<nr>, plus één losse herhaling met `-k` bij een mislukte test), en noem dat akkoord in de opdracht."
- Zet in de opdracht: "Na een release-E2E in een eigen project is `secrets/api_token` van de dev-stack ongeldig; zeg wie een nieuw token voor de dev-stack maakt, want een herstart van de integratiecontainer is niet genoeg."
