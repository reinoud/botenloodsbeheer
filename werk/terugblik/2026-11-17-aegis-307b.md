# Terugblik aegis, nareview #307 (herstel AEG-01)

Datum: 2026-11-17
Taak: nareview van het herstel van AEG-01 en de ADR-zin uit de review van Sentinel, vóór de commit van issue #307. Oordeel: akkoord.

## Wat ging goed

De opdracht noemde de eerdere bevinding, de diff van het herstel, de volledige diff en wat de regie al had getoetst, met de mutant. Daardoor kon ik direct op de drie vragen toetsen en hoefde ik de suite niet zelf te draaien.

## Wat kon beter

Mijn eerste proef draaide ik met de lokale python3, zonder Flask. De overlay (regel 97) zegt dat een losse controle in de webcontainer draait. Dat had ik vooraf moeten lezen.

## Wat deed ik zelf goed

Ik heb per vorm van de opzegdatum laten zien wat de telling doet (leeg, ISO, DD-MM-JJJJ, spatie, getal, tijdstip, 30 februari, 9999-12-31), met de echte `valideer` in de webcontainer. Ook heb ik nagelopen of de nieuwe test zonder `gezien.add` zou falen: dat doet hij, via `uit_bron_op` van lid 1.

## Wat heb ik onderweg verbeterd

Ik zag dat ook een ongeldige `lid_sinds` een record buiten de teller houdt. Ik heb nagekeken waar de bron die datum vandaan haalt (`Def3`, ongewijzigd doorgegeven) en dat als informatiepunt opgenomen, zonder er een blokkade van te maken.

## Wat kan structureel beter in de opdracht

De opdracht zei niet waar een losse proef met de code van de app moet draaien. Bij een worktree is dat niet vanzelfsprekend, want de webcontainer draait de code van de hoofdmap.

## Regel voor de regie

Zet in de opdracht: "Een proef met code van de app draait in de webcontainer (`docker compose exec -T web python -`); controleer eerst dat de geraakte functies in de diff niet gewijzigd zijn, want de container draait de hoofdmap en niet de worktree."
