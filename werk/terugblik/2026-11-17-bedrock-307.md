# Terugblik Bedrock, issue #307 (veiligheidsgrens telt opgezegde records mee)

Datum: 2026-11-17. Taak: teller van de veiligheidsgrens in `synchroniseer` herstellen, tests, ADR-004 en architectuur bijwerken.

## Wat ging goed

De opdracht was scherp: bronnen in volgorde, een duidelijke wijziging en een eigen testdatabase. De fix is klein (een teller in de bestaande lus).

## Wat kon beter

Twee bestaande tests (`opzegging_maakt_oud_lid...`, `bestaand_lid_dat_opzegt...`) importeerden één lid dat daarna opzegt. Dat valt nu terecht onder de grens (0 van 1 actief). De opdracht noemde dat gevolg niet. Ook werkt de beschreven conftest-aanpak niet: `from tests.unit.conftest import *` kan `TEST_DB` niet omzetten, omdat `db_url` de waarde als standaardargument vastlegt.

## Wat deed je zelf goed

De mutant (oude telling) draaide ik echt: twee tests falen, de overige slagen. De derde nieuwe test (volledige bron) is een doorlaattest en faalt bij de mutant niet, dat is bedoeld. Ongeldige records met een geldig lidnummer blijven meetellen, zoals bij `gezien`; dat staat in ADR-004 stap 3.

## Wat heb je onderweg verbeterd

Een kopie van `tests/unit/conftest.py` met `TEST_DB` vervangen, als bind mount, in plaats van de import-aanpak. Docstring van `synchroniseer` bijgewerkt. Een `run.sh` in de scratchpad, omdat de worktree-bewaking een lange `docker compose run`-regel met paden buiten de worktree weigerde.

## Wat kan structureel beter in de opdracht

Geef bij een eigen testdatabase de werkende methode (sed-kopie van de conftest) en meld dat de worktree-bewaking lange compose-regels weigert: gebruik een script. Noem dat een wijziging van de grens bestaande tests kan raken die één lid laten opzeggen.

## Regel voor de regie

Zet in de opdracht: "Een eigen testdatabase maak je met een sed-kopie van `tests/unit/conftest.py` waarin `TEST_DB` is vervangen, als bind mount; `from ... import *` werkt niet omdat `db_url` de naam als standaardargument vastlegt. Draai docker compose via een script in de scratchpad."
