# Terugblik aegis, securityreview #231

Datum: 2026-11-11
Taak: securityreview van de gestagede diff op `fix/231-zone-index` (zone-index in de token-whitelist weigeren).

## Wat ging goed

De opdracht noemde het securitypad, de vragen en de grenzen (geen suite, geen `botenloods_test`, leesquery's alleen via stdin). Daardoor kon ik gericht werken en botste ik niet met Sentinel.

## Wat kon beter

De opdracht liet live of statisch open voor het logcriterium. Voor deze wijziging was statisch genoeg: de controle weigert vóór elke databaseschrijfactie. Een korte zin "statisch volstaat als de weigering vóór de database valt" had een afweging gescheeld.

## Wat deed ik zelf goed

Ik heb de randgevallen niet uit het hoofd beoordeeld, maar in de container met Python 3.14 laten parsen en de genormaliseerde vormen in PostgreSQL als `cidr` gecast. Zo is de vraag "accepteert Python iets wat `cidr` weigert" met bewijs beantwoord, niet met een redenering.

## Wat heb ik onderweg verbeterd

Ik heb de echte `whitelist_lezen` uit de draaiende container aangeroepen, zonder database, om zeker te weten dat `web` de gestagede code draait en niet alleen mijn kopie van de logica.

## Wat kan structureel beter

Zet in de opdracht: "Bij een invoercontrole vóór een databasekolom: laat de reviewer de door Python genormaliseerde vormen met een leesquery naar het kolomtype casten (`SELECT '<waarde>'::<type>`), in de gedeelde database via stdin."
