# Terugblik Pipeline, releasecontroles v2.1.0 (#347)

Datum: 2026-11-19. Taak: unitsuite, trivy en twee E2E-runs op 4685475.

## Wat ging goed
Alle drie de criteria groen bij de eerste poging; de overlay (v0.6.0) liet geen ruimte voor de amd64/qemu-valkuil. Vorige release (#344) gaf een exact format voor het verslag.

## Wat kon beter
De opdracht zegt "verse stack" maar niet hoe. Ik moest zelf afleiden dat het een eigen project is (COMPOSE_PROJECT_NAME, KOPPELNET, INSTALLATIE) met een override zonder hostpoorten, en dat `botenloods-app:latest` ouder was dan de releasecommit (09:44, commit be0f6e4 om 15:48), dus eigen native build onder een eigen tag nodig was.

## Wat deed ik zelf goed
Imagetag per run eigen (`e2e347`), geen `latest` of `botenloods-dev` aangeraakt; stack tussen run 1 en 2 met `down -v` vers gemaakt; getelde aantallen met een script; na afloop images, volumes en netwerken gecontroleerd.

## Wat heb ik onderweg zelf verbeterd
Eerst zou ik de dev-stack hergebruiken; dat botst met "dev-stack blijft zoals hij was" en met poorten 8080/5432. Overgestapt op eigen project en een override in de scratchpad.

## Wat kan structureel beter
- Zet in de opdracht: "Draai de E2E in een eigen project (`COMPOSE_PROJECT_NAME`, `KOPPELNET=10.213.0.0/24`, `INSTALLATIE`) met een override die `ports` leegt en de images `botenloods-app:<tag>` en `botenloods-integratie:<tag>` native bouwt vanaf de releasecommit; controleer vooraf dat `botenloods-app:latest` niet ouder is dan de laatste wijziging in `app/`."
- Zet in de overlay een vast script of compose-override voor de release-E2E, zodat elke agent dezelfde opzet draait.
- `draai.sh` overschrijft `secrets/api_token` van de gedeelde werkmap, ook bij een eigen project; meld dat in de opdracht aan de regie.
